# Marca-Página — Plano de Implementação: Acervo

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sair de um banco sem um único livro para uma biblioteca catalogável em série. Ao fim deste plano, a coordenação bipa um ISBN, confere o que voltou de Google Books ou Open Library, salva, e o cursor já está esperando o próximo ISBN — com N exemplares criados, tombos sequenciais atribuídos e etiquetas prontas para imprimir.

**Architecture:** As mesmas camadas da Fundação. A novidade é o **provedor de metadados**: uma interface (`ProvedorDeMetadados`) com duas implementações (Google Books, Open Library) e um compositor que tenta uma e cai para a outra. Serviço nenhum conhece `fetch` — recebe o provedor por injeção, exatamente como recebe repositório. É o que permite testar a cascata de fallback sem rede.

**Tech Stack:** o da Fundação, mais `pdf-lib` (etiquetas) e `xlsx` (importador). Nada mais.

**Spec:** `docs/superpowers/specs/2026-09-09-biblioteca-escolar-design.md` §2.2, §2.6, §4.2, §4.5, §5.5, §5.7

## Global Constraints

As doze invariantes do plano da Fundação continuam valendo integralmente. Este plano acrescenta três, e resolve uma contradição que a Fundação deixou em aberto.

### A contradição, e como se resolve

A Fundação afirma duas coisas que, juntas, não fecham:

- **Constraint 4:** serviços não conhecem `Request`, `cookies()` nem `headers()`.
- **Constraint 5:** autorização mora no serviço; todo serviço protegido chama `requirePermission`.

Mas `requirePermission()` lê a sessão pelo cookie. Um serviço que o chama passa a depender de HTTP, deixa de ser testável sem simular requisição, e a Constraint 4 morre em silêncio — o teste de arquitetura não pegaria, porque ele só olha importações **diretas** de `next/*`.

**Decisão (13):** o serviço recebe o `Principal` como parâmetro e chama a função **pura** `exigirPermissao(principal, 'obra:criar')`. Quem lê a sessão é a rota, com `requireStaff()`, e passa o principal adiante.

A autorização continua morando no serviço — ele decide e ele recusa; esconder o botão na UI segue não sendo autorização. O que sai do serviço é apenas o *transporte* da identidade. O ganho é concreto: dá para testar "MONITOR não consegue excluir obra" sem levantar servidor.

```ts
// certo — o serviço exige e recusa, sem saber o que é um cookie
export async function excluirObra(
  principal: Principal,
  entrada: { obraId: string },
  deps: DependenciasDeObras,
): Promise<void> {
  exigirPermissao(principal, 'obra:excluir')
  // ...
}

// errado — o serviço passa a depender de HTTP
export async function excluirObra(entrada: { obraId: string }) {
  const principal = await requirePermission('obra:excluir') // não faça isto
}
```

### Invariantes novas

13. **Serviço não lê sessão.** Recebe `Principal` por parâmetro e usa `exigirPermissao`. Nenhum `*.service.ts` importa `@/core/auth/guards` nem `@/core/auth/sessao`. **Verificado por teste** (Tarefa 1).
14. **Nada de `fetch` fora de `src/infra/`.** Serviços e repositórios recebem provedores por injeção. **Verificado por teste** (Tarefa 1). Sem isso, testar o fallback entre Google Books e Open Library exigiria rede — e um teste que depende de rede é um teste que falha na sexta-feira por motivo alheio ao código.
15. **Tombo é gerado pelo sistema, nunca digitado em cadastro.** Ele é o identificador físico da cópia; deixar digitar convida a colisão e a rasura. A única exceção é a importação de acervo pré-existente, que recebe tombo explícito e valida unicidade.

export function normalizarNomeDeAutor(nome: string): string {
  return nome
    .normalize('NFD')

## O que este plano deliberadamente NÃO entrega

- **Empréstimo de exemplar.** `SituacaoDoExemplar` já prevê `EMPRESTADO`, mas quem a muda é a Circulação (m-2). Aqui a situação só muda por baixa e manutenção.
- **Leitura de código de barras por câmera.** Leitor USB funciona como teclado e já está contemplado; câmera exigiria visão computacional no cliente e fica fora do v1 (spec §7).
- **Capa hospedada por nós.** Sempre URL externa. Se a URL morrer, a ficha fica sem capa — aceito conscientemente contra 0,5 GB de banco.
- **Reserva a partir da busca no acervo.** É m-2.
